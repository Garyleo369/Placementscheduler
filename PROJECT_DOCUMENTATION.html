Enterprise Technical Report

Placement Week Scheduler

Autonomous Placement Operations & Surgical Replanning Platform

1. Project Overview & Problem Statement

University campus placements present a complex, multi-dimensional combinatorial optimization problem. During an intensive 4-day placement cycle, hundreds of students (800+) compete across 35 multi-tier corporate recruiters, dozens of parallel interviewing panels, and limited campus room facilities (20 rooms across 4 floors).

Standard manual or naive scheduling approaches fail due to:

  • Multi-shortlisting conflicts: Top-tier students shortlisted simultaneously across multiple companies, causing double-booking.
  • Room capacity bottlenecks: Severe physical constraint starvation during peak interviewing hours.
  • Unforeseen real-time campus disruptions: Recruiter transit delays, panel dropouts, room outages, or candidate withdrawals. Traditional systems regenerate the schedule entirely, creating chaotic cascading disruptions for hundreds of unaffected candidates.

The Placement Week Scheduler solves this through an autonomous MERN platform featuring a high-throughput Greedy Earliest-Available-Slot (EAS) scheduler and a groundbreaking Surgical Replanning Engine that handles disruptions with zero schedule churn on locked slots.

2. Architecture & The MERN Stack Implementation

The system follows a strict, decoupled MERN architecture (MongoDB, Express.js, React.js, Node.js) ensuring high performance, fault isolation, and reactive UX:

M MongoDB & Mongoose ODM

Relational document modeling with strict constraints, schema validations, aggregation pipelines for real-time analytics, and high-throughput bulk write operations.

  • Company (Tiers 1-3, priorities, operating days/hours, shortlists)
  • Student (Roll number, CGPA, department, shortlist references)
  • Room (Physical capacity, building, floor index)
  • Panel (Company affiliation, interviewer roster)
  • Interview (Time slots, status lifecycle, conflict reasons)

E Express.js REST API

Modular, decoupled RESTful API endpoints serving client queries, coordinating background scheduling tasks, and providing granular status codes.

  • /api/health (Liveness probe and system uptime)
  • /api/data (Synthetic data generation & status summary)
  • /api/schedule (Master schedule generation, filters, aggregations)
  • /api/replan (Disruption handler, diff generator, audit logs)

R React.js & Vite Client

Responsive dashboard with dark-mode aesthetic, live metric cards, interactive disruption simulation modal, and visual before/after replan diff audits.

  • MetricCards (Scheduled rate, conflicts, room utilization, churn)
  • ScheduleTable (Day/status filters, company search, pagination)
  • AlertsPanel (Bottleneck constraint breakdown)
  • ReplanModal & ReplanResult (Interactive simulation)

N Node.js Algorithmic Core

Non-blocking execution of greedy heuristic scheduling and multi-phase surgical replanning algorithms in pure memory.

  • Integer-minute time representation (09:00 = 540 min)
  • O(1) Hash Map interval collision lookups
  • Round-robin panel load balancing
  • Penalty cost optimization for disruption replanning

3. Core Algorithms & Scheduling Logic

3.1 Greedy Earliest-Available-Slot (EAS) Scheduler

The master scheduling engine (server/src/services/scheduler.js) executes a single-pass, explainable heuristic:

  1. Company Priority Sorting: Companies are ordered ascending by priority (Tier 1 first, ensuring premier recruiters receive prime scheduling windows).
  2. Student Merit Sorting: Within each company shortlist, candidates are sorted descending by CGPA.
  3. Panel Load Balancing: Candidates are evenly distributed across the company's parallel interviewing panels using round-robin bucketing.
  4. Conflict-Free Slot Search: For each candidate, the panel cursor probes prospective time slots:
    • Company Window Check: Ensures slot $[t, t + \text{duration}) \le \text{windowEnd}$.
    • Student Conflict Check: Verifies student is not already interviewing in another room. If busy, advances cursor by 5-minute increments (up to 50 retries).
    • Room Allocation: Identifies the first vacant physical room across campus.
  5. Explicit Failure Attribution: If any constraint fails, the interview record is tagged with an explicit classification: NO_STUDENT_AVAILABILITY, NO_ROOM_AVAILABLE, or COMPANY_WINDOW_EXPIRED.

3.2 Surgical Replanner Engine & Penalty Function

When disruptions strike during live placement days, naive systems rebuild the entire master schedule. The Placement Week Scheduler uses a 4-phase surgical approach (server/src/services/replanner.js):

  • Phase 1 (Impact Analysis): Identifies strictly the interviews broken by the disruption (e.g., morning slots for a delayed company, or slots inside an unavailable room).
  • Phase 2 (State Reconstruction): Unaffected interviews are locked. Slot reservation maps for students, rooms, and panels are constructed using only locked interviews.
  • Phase 3 (Scored Rescheduling): Every affected interview evaluates all feasible slots across remaining days, panels, and rooms. Each feasible slot is evaluated using a calibrated disruption-penalty function:
Score = 50 × Δday + 20 × Δpanel + 10 × Δroom + 1 × (ΔWaitMinutes / 5)

The candidate slot with the lowest score (minimum disruption) is booked. If no slot satisfies all hard constraints, the interview is marked cancelled.

  • Phase 4 (Diff & Churn Generation): Compares original vs new states to produce a granular diff report (displaying changed days, times, panels, or rooms) and calculates the exact schedule churn percentage.

4. Disruption Scenarios & Real-World Use Cases

Disruption Type Campus Event Trigger Surgical Handling Behavior
COMPANY_DELAY Company HR/interviewers delayed by 1-2 hours due to flight/traffic. Only morning interviews falling within the delay window are moved to later afternoon slots or subsequent company operating days.
PANEL_DROP An interviewer panel abruptly drops out (illness or tech failure). Candidates assigned to that panel are distributed across the company's remaining active panels without exceeding room limits.
ROOM_UNAVAILABLE Facility maintenance, power failure, or AV issue blocks a room. The room is blocked for that day; all its scheduled interviews are re-allocated to other vacant campus rooms.
STUDENT_WITHDRAW Candidate accepts an off-campus offer or withdraws. All interviews for that student are cancelled, instantly opening up panel and room slots for replanning.

5. REST API Specification

Endpoint Method Payload / Parameters Description
/api/health GET — System health, uptime, and database connection status.
/api/data/generate POST { totalStudents: 800, clearExisting: true } Synthesizes 35 companies, 800 candidates, 20 rooms, and panels.
/api/data/summary GET — Returns entity count overview in database.
/api/schedule/generate POST { clearExisting: true } Executes greedy EAS scheduler and persists master interviews.
/api/schedule GET ?day=1&status=scheduled&page=1&limit=50 Retrieves paginated interviews with multi-criteria filters.
/api/schedule/summary GET — Computes overall scheduling rate and failure breakdown aggregation.
/api/replan POST { type: "COMPANY_DELAY", companyId, delayMinutes: 60 } Applies disruption, performs surgical replan, returns before/after diff.
/api/replan/ids GET — Helper returning valid IDs for 1-click interactive simulation.

6. Installation & Execution Guide

Step 1: Start Backend (Express & Node.js)

cd server
npm install
npm run dev

The backend will start at http://localhost:5000 with auto-reload via Nodemon.

Step 2: Start Frontend (React & Vite)

cd client
npm install
npm run dev

The client application will start at http://localhost:5173.

Step 3: Operating the Application

  1. Navigate to http://localhost:5173 in your web browser.
  2. Click "Generate Realistic Data" in the top header to seed the database with 35 companies, 800 candidates, and 20 rooms.
  3. Click "Run EAS Scheduler" to generate the conflict-free master schedule.
  4. Observe real-time KPI metric cards, room utilization, and constraint bottleneck breakdowns.
  5. Click "Simulate Disruption" to test any of the 4 disruption types and inspect the surgical before/after diff report.
